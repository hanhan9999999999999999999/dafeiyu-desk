## 9. v1.0.0 追加（2026-11-12）

v0.2.0 留下的两个缺口——「没有第二套真实模型交叉验证」和「规则只验证了内置 6 条」——这一版都补上了。

### 9.1 第二套真实模型：mianfeimodelYUAN

拿到的模型（`D:\document\DSH Live2D\mianfeimodelYUAN`）正好是「脏数据」的典型：

- `model.model3.json` 的 `FileReferences` 只有 `Moc / Textures / Physics / DisplayInfo`，**没有任何 `Motions` / `Expressions` 声明**；
- 目录里却躺着 `motions/idle.motion3.json` 和 `expressions/` 下 19 个 `.exp3.json`；
- 单张贴图（`model.8192/texture_00.png`），98 个参数，没有 cdi3。

v0.2.0 的探测只读声明，所以这个模型导进来会是「0 动作 / 0 表情」。这一版加了两件事：

1. **未声明素材扫描**（`probe.js`）：从模型文件所在目录递归 3 层，收集未登记的 `*.motion3.json` / `*.exp3.json`，动作归到父目录名分组，表情用文件名做 name，标 `declared:false`，并在体检里给出「有 N 个动作/表情文件没有在模型清单里声明，已自动收进素材库」。
2. **动作时长轻量读取**：motion3 的 `Meta.Duration` 在文件末尾，整份 parse 对几十 MB 的文件太贵；改成读头 4KB + 尾 4KB，正则取 `"Duration"`，失败返回 0。

实测结果（`_test/t-pack-zip.js`，离线跑 `ModelAdapter`）：27 个文件、98 参数、1 贴图；动作清单 1 条（`motions/idle.motion3.json`，6.0s，未声明）；表情 19 个（未声明）；导入后 `pet.json` 落在 `models/model/`，`displayName=yuan`。

live 验证（Electron 真跑）：

- 文件夹导入 → 切换 → 主窗口加载成功，画面是这只粉白裙子的 Q 版角色；
- zip 导入（`_test/tmp/yuan.zip`，12.5MB，含外层目录）→ 自动剥壳 → 生成 `model-2`；
- `FishModel.playFile("motions/idle.motion3.json")` → `{ok:true,dur:5,curves:3,loop:true}`；
- 存一组非默认 tuning（angleMaxX 40 / physicsDt 16 / maskResolution 512 / motionSpeed 1.25）→ 切换 → 渲染端 `FishModel.tuning()` 原样读回。

### 9.2 新增规则：`70-tuning.js`

16 个字段，5 组（头部 / 全身 / 眼睛 / 物理与渲染 / 动作）。写进 `live2d.tuning`，`getManifest()` 以 `tuning` 字段下发给渲染端。

为什么放在「模型包」而不是「全局设置」：不同模型的可动范围差别很大——Q 版转头 15° 就夸张，等身模型 30° 才自然；同一个物理文件在 30fps 和 60fps 下的表现也不同。放在包里，换模型各自独立；默认值按 0.2.0 的写死倍率反推（26 / 30 / 14 / 0.07），升级后手感不变。

**踩坑（第二次）**：`manifest.sanitize()` 用 `blank()` 重建 `live2d`，再按白名单逐字段拷贝。`tuning` 没进白名单，保存接口返回 `{ok:true}`、读回来还是默认值。这和 `layout.viewY`、`interaction` 是同一个坑。修法：白名单补 `L.tuning`，`blank()` 的默认对象也补齐；同时把这条写进 `verify:packs` 的「所有规则存盘→读回」检查里。

### 9.3 渲染端接入

`renderer.js` 新增 `TUNE` / `syncTune()` / `applyTuningToModel()`：

- `syncTune(pack)`：逐键合并 + 逐项 clamp（防止 NaN 或越界把模型写没）；
- `applyParams()`：角度倍率从常数改成 `TUNE.angleMaxX/4.2` 这类换算；新增 `ParamBodyAngleY/Z`；眼珠乘 `eyeGain` 并夹在 `±eyeMax`；
- 物理：把 `physics.evaluate` 包一层，单帧 dt 压到 `physicsDt` 毫秒（0 = 关）；
- 遮罩：`renderer.setClippingMaskBufferSize(size)`，只在模型加载后首帧前调一次（Cubism 运行中改会崩）；
- 动作：`launchMotion` 记录 `speed`，播放时间乘它；淡入淡出乘 `fadeScale`；交叉淡化时长也乘；
- 参数锁：`lockFor()` / `lockModelMotion()` 把动作曲线里的参数名塞进 `__motionOwn`，`put2()` 每帧跳过；TTL = 时长 / 速度 + 0.8s；`Idle` 组默认不锁。

### 9.4 动作文件引擎

语义层第 4 种动作来源：`file:<包内相对路径>`。

- `encodeAction`：`engine==="file"` → `"file:"+rel`；
- `decodeAction`：`file:` → `{engine:"file",file:rel,name:basename}`；
- `20-actions` 规则校验：rel 为空报 `action-file-empty`；包里找不到报 `action-file-missing`；
- `manifest.sanitize()` 的 `actions.overrides` 认这个字段；
- 渲染端 `actionFor()` 遇到 `engine:"file"` → `FishModel.playFile()`。

`src/motion3.js` 是配套的解析器（UMD，浏览器 / Node 都能用）：只取 `Target==="Parameter"` 的曲线，支持 Linear / Bezier / Stepped / InverseStepped，贝塞尔用 24 次二分反解 x，采样步长按 `Meta.Fps`（默认 30）。实测那份 idle 动作：3 条曲线（`Paramcry1/2`、`Paramyincang`）、每条 154 个采样点、时间严格单调。

### 9.5 ZIP 导入

`src/packs/zip.js` 纯 Node 实现（`fs` + `zlib`），因为发行包不带 `node_modules`，7-Zip 二进制不在安装包里。

- 支持 method 0 / 8；明确拒绝加密、BZIP2、LZMA、ZIP64；
- 文件名：UTF-8 flag 优先；否则先试 UTF-8（含替换字符则失败），再 `TextDecoder("gbk")`，最后 latin1；
- 安全：路径穿越、盘符、`__MACOSX`、`._*`、`.DS_Store` 全部过滤；单文件 >260MB、总量 >1.4GB、文件数 >6000 拒绝；压缩比 >220 且解压后 >8MB 视为炸弹丢弃；
- 解完自动找最浅的 `.model3.json`，唯一子目录时剥壳。

### 9.6 适配器素材库

右栏底部新增折叠块：

- 动作：组 / 序号 / 文件名 / 时长 / 已声明或未声明 / ▶ 试播；
- 表情：name / 已声明或未声明 / ▶ 试播 / 设为默认；
- 绑定栏：选动作 → 选语义槽 → 「绑到槽」写 `cfgOf("actions")[slot] = "file:"+file`，同时同步「动作映射」里的下拉值。

试播走 `FishMotion3.parse` + `paramMapNow()` 把曲线参数名映射成索引；全部落空时提示「这支动作驱动的参数这个模型没有」，而不是静默不动。

### 9.7 设置中心

`settings.html` 重写成侧栏七页签 + 页内分组 + 卡片，`settings-shell.js` 负责导航与概览；`settings-renderer.js` 只按 id 找元素，所以业务逻辑零改动（全部旧 id 保留，`verify:src` 308 项通过）。

窗口尺寸 420×720 → 900×660（可拉伸、可最小化），`openSettings()` 同步改。

### 9.8 已知边界

- 遮罩精度只能在模型加载后首帧前设置；运行中改需要重新加载模型（现在是保存后由 `pack-changed` 触发 reload，符合这个约束）。
- 物理步长是「封顶」不是「固定步长」：帧率高于设定值时按真实 dt 走，低于时不会过冲。
- 动作快捷键（给每个场景绑一个全局热键）这一版没做；现在只有说话 / 唤出 / 伸懒腰三个固定热键。
- 表情试播走的是模型的 `expression(name)`，不经过我们自己的 exp3 叠加器；要看叠加效果得在主窗口里触发。

## 10. v1.1.0：取景并入适配器 + 程序与模型分离

### 10.1 为什么把取景搬进适配器

1.0.0 有两套取景存法：全局 `settings.viewBox`（旧取景窗写的）和模型 `pet.json` 的 `layout`（适配器写的）。同一个东西两个入口、两个存储，切模型时就会漂——渲染端还要判断 `vb.pack === PACK.id` 才敢用全局那份。1.1.0 把它收敛成一条：

- 唯一来源 = `PACK.layout.viewY / viewH`；
- 唯一入口 = 适配器第 4 步「取景与布局」；
- 渲染端删掉 `settings.viewBox` 的优先分支与 `onSettingsChanged` 里应用 viewBox 的分支；
- 旧全局 `viewBox` 在打开对应模型时搬进 `layout` 并清空（一次性，toast 提示确认后保存）。

`viewframe.html / viewframe.js` 删除；`viewframe:open` IPC 保留但改为 `openAdapter("", "layout")`，托盘与设置页走同一条。

### 10.2 取景交互的三个视图

- **普通视图**：整只模型居中，框按主窗口宽高比（`460/560`）画，拖框改 `viewY`，拖边改 `viewH`。
- **主窗口视图**（`S.crop`）：预览中间切一个 `min(W, H*460/560)` 的竖口，两侧 `.vf-mask` 压暗；模型按 `scale=(H*0.995)/(mh*viewH)` 放大，使取景那一段正好铺满竖口。这解决「框里看着对、桌面上不一样」的老问题——两者是同一段像素。
- **滚轮缩放**：以指针为锚，`k=1.06`，`viewH` 夹在 0.06..1.3，`viewY` 夹在 -0.2..0.95；缩放时同步滑杆与读数。

推荐取景走规则层的 `detect(ctx)`：参数里出现 leg/knee/foot/足 → 全身（`0.02 / 0.96`），否则半身（`0.08 / 0.55`）。接口是 `GET /api/packs/<id>/recommend`（路由段只允许小写字母，所以不叫 `recommend-layout`）。

### 10.3 安装包不再带模型

- `build.extraResources` 删掉 `model/`；安装包从 942 MB 降到 **896 MB**。
- `scripts/verify-pack.js` 三条红线：`resources/model` 不存在、`resources` 下无散落 `.moc3/.model3.json`、`app.asar` 内无这两类文件。
- `LICENSE.txt` 第二节重写为「程序与模型分离发行」：说明包里没有模型、导入只复制到用户目录、原作者的禁止再分发条款、用户自带模型的授权自负。

### 10.4 没有模型时的四种界面

| 位置 | 表现 |
|---|---|
| 主窗口 | `#noModel` 导入卡（`.nm-card` 292px），两个按钮走 `model:import` IPC（folder / zip 分两个入口，因为 Windows 文件对话框不能同时选文件和目录）；`#dock` 隐藏 |
| 主窗口尺寸 | `windowSize()` 里 `hasUsablePack()` 为假 → 356×512；导入/切换后 `doResize()` 按缩放长回正常尺寸 |
| 适配器 | 模型库为空时预览插 `.wel` 导入面板；`select()` 时移除 |
| 欢迎页 | `welcome.js` 拉 `/api/packs/active`，没有模型就显示 `.nomo` 提示；`openWelcome` 在 `did-finish-load` 后按 `.card` 高度 `setContentSize`（写死 368 会切掉按钮） |

### 10.5 模型包 id 的命名

1.0.0 用 `path.basename(model3)` 生成 id，而大量模型的文件就叫 `model.model3.json`，于是导入第二只开始变成 `model-2 / model-3`。1.1.0 改成优先用用户选中的文件夹名（zip 则是压缩包内层目录名），拿不到才退回模型文件名。

### 10.6 已知边界

- 主窗口在空状态时的尺寸是固定的 356×512，不跟随「大小」滑杆；导入模型后立即按滑杆恢复。
- 「主窗口视图」的宽高比写死为 `460/560`（`BASE_W/BASE_H`），与缩放无关；改基准尺寸要同步改 `adapter.js` 的 `WIN_AR`。
- 迁移旧 `viewBox` 只在包可写（`r.writable`）时进行；只读的内置包保持原样。
