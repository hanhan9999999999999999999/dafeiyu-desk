## 一、本机服务不再谁都能喊

程序在本机开了一个小 HTTP 服务（`127.0.0.1:7801` 起）。以前它只靠「绑在回环地址」当边界——
任何你访问的网页都能悄悄给它发一个不触发预检的请求。实测这条链路是通的：
跨站 `POST /usage/clear` 返回 200，用量计数真的被清零；伪造 `Host` 也能过，DNS rebinding
之后能读回本机任意路径的存在性（`/api/packs/check?path=…`）。

现在每个请求先过一道来源校验：

- `Host` 必须是回环地址，且端口等于实际监听端口（`listen(0)` 随机端口时按真实端口比）；
- `Origin` 存在时必须是同端口的回环来源；`Origin: null` 一律拒；
- `Sec-Fetch-Site: cross-site` 直接拒；
- 不通过回 403，并在 `run.log` 记一行 `[server] 拒绝可疑来源 origin=… host=…`。

本机脚本（不带 `Origin`）照旧放行，所以命令行、模型包工具、自检脚本都不受影响。

## 二、出错时说清哪一步坏了

- **RVC**：失败分支里引用了作用域外的变量，求值即抛 `ReferenceError`，客户端拿到的是
  `500 e is not defined`，引擎返回的真实原因（例如「模型文件损坏」）全被吞掉。现在透传上游状态码与正文。
- **子进程**：rvc、随身桥接、三个安装器共 5 处 `spawn` 原先没挂 `error` 监听。
  `EACCES`、被安全软件拦下时状态机以为进程起来了，错误只落到全局兜底。现在各自记进
  `rvcLastError` / `miniLastError` / 安装日志，界面能说出来。
- **诊断目录**：`diag:open` 原先把渲染层传来的路径直接交给 `shell.openPath`（对 `.exe` 就是执行），
  现在只允许打开用户数据目录下的诊断目录。

## 三、密钥不再明文躺在盘上

`apiKey` / `seeKey` 改用 Electron `safeStorage` 加密（Windows 上走 DPAPI，密文绑当前账户），
写在 `settings.json` 顶层 `secure` 区，形如 `safe1:<base64>`。

- **一次性迁移**：第一次用这一版启动时，盘上的旧明文会被加密写回，之后不再迁移。
- **四种状态照实报**：`encrypted` / `plaintext`（没有密钥库）/ `locked`（有密文但这次没加密器）/
  `error`（解不开）。后两种**密文原样保留**，不销毁、不假装成功；设置页会说「密钥解不开
  （换过 Windows 账户或系统密钥库被重置），请重新填写」。
- **设置页只显示首尾**：`前三 + •••• + 后四位`；没改动就不提交，所以「测试连通」不会拿掩码去请求。
- **边界照实说**：同账户下的恶意进程、以及主窗口渲染层（语音在渲染层直接发请求）仍然拿得到明文。
  这次解决的是「配置文件被拷走 / 被同步盘上传 / 被截图」这一类。

真机验证：`scripts/test-secrets.js` 11 条断言，加一次在 Electron 35.7.5 主进程里用真 DPAPI 的
15 项探针（密文改一字节即抛错、无加密器时密文存活、恢复后能解开）全部通过。

## 四、发行：签名位置就位，差一张证书

- `build.win.signAndEditExecutable: true`：`[stamp] exe 图标与版本信息已写入`，
  主程序版本资源为 `1.6.5.0`、公司名「小代码酱」、产品名「大肥鱼」。
- `signtoolOptions.signingHashAlgorithms: ["sha256"]`；`forceCodeSigning: false`——没有证书也能出包，
  构建不会被卡死。
- 新增 `npm run sign:check`：读 `dist` 里的 exe，打印版本资源与 Authenticode 状态；
  `--strict` 时未签名即 exit 1，可以接进 CI。
- **这个包仍然是未签名的**（`Status=2`）。SmartScreen 会拦一次「Windows 已保护你的电脑」，
  企业策略下可能直接不让装。证书怎么买、怎么接进构建机见
  [发行-签名与密钥](发行-签名与密钥.md)。

## 五、版本号

`package.json` 从 `1.3.2` 补到 `1.6.5`（`package-lock.json` 里漂着的 `1.4.0` 也一并对齐）。
1.4 / 1.5 / 1.6 三串只改了代码没改 `version`，而「检查更新」是拿 `app.getVersion()` 与 Releases
标签比的——一直停在 1.3.2，每个用户都会被提示有新版本。

## 六、装之前 / 装之后

- **覆盖安装**：直接运行安装包即可，用户数据（设置、聊天记录、模型包）在 `%APPDATA%\dafeiyu-desk`，
  卸载与覆盖都不会删（`deleteAppDataOnUninstall: false`）。
- **升级后第一次启动**：如果配置里存过密钥，会在这一秒被加密写回；日志里能看到
  `[main] 密钥存储：encrypted`。
- **换过 Windows 账户 / 重置过系统密钥库**：密钥解不开，设置页会提示重新填写，旧密文留着不毁。
- **回滚**：重装 1.3.2 的安装包即可；`settings.json` 里的 `secure` 区对旧版是未知字段，
  旧版会忽略它，但**密钥在旧版里是空的**，需要在设置里重填一次。
