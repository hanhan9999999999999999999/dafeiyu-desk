# 语音提速说明（1.6.0，尚未打包）

发布日期：2026-11-15

这一版只做一件事：**让她开口变快**。飞鱼（CosyVoice3）原来你说完话要等两秒半到三秒才听见第一个字，
长一点的回复中间还会断上两三秒；现在首声 1.6–2.0 秒，整段总时长也短了两成，而且音色不会一句话换一个人。

关键是「没有砍质量」：模型、权重、声线、参考音频、采样率、fp16 开关一个都没动。
同样的模型，同样的声音，只是不再把时间浪费在准备和排队上。

## 快了多少

用三条真实长度的句子量（RTX 4060 / fp32；每条都重启引擎、清空缓存、单独一个进程跑，
改后取 3 次冷启动的中位，因为单次有 ±0.5 秒的 GPU 调度波动）：

| 用例 | 改前 首声 / 总时长 | 改后 首声 / 总时长（中位） |
|---|---|---|
| 「嗯，我在呢。」（6 字） | 2.58s / 2.58s | **1.79s / 2.37s** |
| 27 字 2 句 | 2.03s / 7.83s | **2.08s / 6.83s** |
| 72 字 3 句 | 3.05s / 17.50s | **1.94s / 15.49s** |

按中位说：**首声 2.58 秒 → 1.94 秒（约 -25%）**，总时长 -10~21%。最快的几次落在 1.5 秒左右，
最慢的一次 2.5 秒（GPU 频率在笔记本上会飘）。
重复的句子（「我在呢」「好呀」这类）本来就有整句缓存，首块 **0.003 秒**、几乎瞬间出声，
这一版把缓存的命中情况也显示出来了（设置里会写「缓存秒回」）。

## 为什么能快，而不换模型

四处白等，逐个拆掉：

1. **模型里有个只增不复位的计数**。流式合成时每隔 25 个 token 吐一次音频，但下一跳会翻倍
   （25 → 50 → 100），而且一段话说完不复位 —— 于是上一句越长，下一句第一块要攒得越多，
   最坏要凑够 100 token（约 4 秒音频）才出声。现在每句开跑前拨回 25，就是模型原本的设计。
   日志里看得见：改前「首块 3.91s」的那句，改后 1.5s。
2. **预热推理原来在请求路径上**。它每次 1.6–2.2 秒，还会因为换参考音而重跑 ——
   等于把两秒冷启动直接压在你等的第一句上。现在只在「引擎启动 / 你点预热」时做，
   而且顺手把 7 条参考音色一次全抽好，之后换情绪不再现抽（省 0.4 秒/句）。
3. **同一段回复里的参考音不再逐句重挑**。客户端是一句一个请求，原来参考音按每句情绪挑，
   一句一个样 —— 听感上是「说着说着换了个配音员」。现在 25 秒内锁定同一条。
4. **播放器从「一块一个新 `<audio>`」换成一根时间轴**。原来每块音频都要新建元素、等它 load，
   块与块之间必然留缝；现在每块解码后按采样级首尾相接排到同一条时间线上，缝没有了。

顺手修掉一个静默坏掉的 bug：声库里原本给「可爱」预设的参考音文件名写错了，
预热每次报 `LibsndfileError`，然后退化成每句重新抽特征（0.3–0.8 秒/句）。
现在参考音有完整回落链，manifest 写错也不会崩在预热上。

## 你现在能在设置里看到

设置 → 概览：多了一张「开口速度」小卡，显示她最近一次开口的实测首声，2 秒内是绿的。
设置 → 声音与行为 → 变声引擎：「引擎状态」卡上多了「首声」和「合成速度」两列
（合成速度 ≤1× 表示算得比播得快；整段命中缓存时直接写「缓存秒回」）。
数字都是引擎自己报上来的，不是估的。

概览那四张小卡现在也能点：当前模型 / 回复来源跳到「连接与模型」，
说话的声音 / 开口速度跳到「变声引擎」，键盘也能停上去按回车。

## 走错的两条路（写给以后改这里的人）

- **不要打开 `torch.backends.cudnn.benchmark`**。流式合成每块的音频长度都不一样，
  每个新长度都会触发一轮卷积算法穷举：同一句话 RTF 从 1.21 掉到 **14.25**，首块从 1.53 秒变 **33 秒**。
- **不要把模型里的 `sleep(0.1)` 轮询压到 0.02**。看着更灵敏，实测更慢（RTF 1.08 vs 0.85），
  是 GIL 争用 —— 这条也写进了回归测试，免得再被「优化」回去。
- `torch.set_num_threads` 保持 4。调到 8/12 时单句要 19–29 秒。
