# 方案总览：LumenAct 表情接入 + 多模型适配

> 本文是 2026-11-15 这一轮全部方案的汇总。已完成的写「已落地」，没做的写「待做」，每条都带风险与验收标准。

---

## 0. 一句话

把 LumenAct 的 97 段真人动捕表情曲线，翻译成她模型能吃的 23 个参数轨道，再接一句「AI 说什么话 → 演什么情绪」，最后把「23 个参数」升级成「23 个能力槽位」，让任何外接模型都能按自己的参数名接进来。

| 钩子 | `say()` 首行 `exprReact(text)` —— 所有台词出口自动带表情 | ✅ |

## 2. 方案 A：情绪对齐（低成本）

**问题**：现在只看「这句话的字面」。她说「主人你别难过」时，字面是「难过」，但演错的是**她自己**——她在安慰，不该跟着哭。

| 子项 | 做法 |
|---|---|
| A1 角色区分 | `exprReact(text, ctx)`，`ctx.role` = `self` / `relay` / `report` / `comfort`。relay 时情绪取反 |
| A2 用上 mood | `say(t, mood)` 的 `mood` 参数全项目没人用。接到 `exprReact` 当先验：mood 已定则优先 mood |
| A3 强度 | `ctx.intensity` 0~1，缩放曲线幅度（`trimCurves` 已有裁剪逻辑可复用） |

- 改动面：`renderer.js` 一个函数 + `say()` 透传
- 风险：低
- 验收：`"别难过啦"` 应演「温柔/微笑」不是「难过流泪」

---

## 3. 方案 B：双轨混音（高收益、高风险）

**问题**：现在表情和手写动作抢**同一条** `__act` 通道。她在演害羞（低头 + 眯眼）时，如果同时伸手摸头，两者必有一个被整份覆盖。

**做法**：把 `__act` 拆成两条轨

```
__act.body  —— 身体动作轨（ParamBodyAngle*、Param36/39/41/42/43 手、Movement1/2/3、Wing*）
__expr      —— 表情轨（EyeSmile、ParamBrow*、Mouthpucker、CheeckPuff、ParamMouthForm、眼睑）
共享参数    —— ParamAngle*、ParamEyeBall*、ParamEyeLOpen/ROpen、ParamMouthOpenY 走 ACT_MERGE
```

| 项 | 说明 |
|---|---|
| 冲突消解 | 参数域硬划分 + 共享区按 ACT_MERGE 规则合成 |
| 改动面 | `applyParams` 1454–1479 段（372 行最密逻辑） |
| 风险 | **高**。改错会让所有动作一起坏，且不易定位 |
| 收益 | 最高。她可以「一边害羞一边摸头」，动作库和表情库自由叠加 |
| 验收 | 982 项全过 + `_act()`/`_expr()` 双轨同时非零 + 真机截图对比 |

**建议**：先做 A/C/D，B 放最后单独一轮做，做前必须打完整快照。

## 4. 方案 C：情绪编排器（中成本）

**问题**：一次回答可能包含多段情绪（先惊讶 → 再思考 → 最后微笑）。现在只演第一段。

| 子项 | 做法 |
|---|---|
| C1 序列化 | 文本切成 2–4 个情绪段，逐段 `expr()`，段间用 `cross` 交叉淡化 |
| C2 合并同类项 | 相邻同标签合并，避免「微笑→微笑」白演一次淡入淡出 |
| C3 时长分配 | 按 `pace` 字段：「反应快」限 3 秒，「缓慢」放 10 秒 |
| C4 用上 subcategory | 现在同标签随机取前 6 段之一。改成按 `subcategory` 语义匹配（「被夸后嘴硬害羞」vs「被夸得不好意思」） |
| C5 用上 environment | 场景先验：「熟人开玩笑」偏「闹别扭」，「陌生场合」偏「拘谨」 |

- **不写编排器也能先做的三件小事**：C4、C3、C5 —— 都是查表，不改架构
- 风险：中
- 验收：一句含 3 种情绪的台词，能连演 3 段且不打架

## 5. 方案 D：多模型地基（你新提的需求，已实作前 3 步）

**问题**：「能不能不只适配一个模型，外接模型后要能匹配上所有功能」。

**核心洞察**：`packs/semantics.js` 早就有这个设计——文件头注释写着「换一个模型就要满文件找常量。现在把『软件需要哪些能力』抽成槽位」。但只抽了 12 个槽，且**表情槽一个都没有**。

### 已落地

| 步骤 | 内容 |
|---|---|
| D1 扩槽 | `PARAM_SLOTS` **12 → 26**。新增 14 个表情槽（eyeSmile / browLY / browRY / browLAngle / browRAngle / browInnerUp / shockL / shockR / cryL / cryR / angry / pupilX / mouthPucker / cheekPuff），每个带 `canon` + `alts` 变体名 + `range` + `gain` |
| D2 补 alts | 老模型常用改名全收：`AngleX`、`EyeOpenL`、`MouthOpen`、`MouthForm`、`Breath` 等 |
| D3 曲线改槽位键 | `build-curves.cjs` 的 TARGETS 从参数名改成槽位 id，`expr-curves.js` 升到 `fish.exprcurves.v2`，`curves` 的键是 `angleX`/`eyeSmile` 而不是 `ParamAngleX`/`EyeSmile` |
| D4 解析器 | `renderer.js` 的 `resolveExprSlot(slotId)`：`PACK.params`（手动绑，最高优先）→ `canon` → `alts` → `slotId` 本身。命中缓存，换模型时 `exprSlotReset()` 清 |
| D5 降级链 | `EXPR_DEGRADE = { eyeSmile: v → eyeLOpen(1 - v*0.45) }`。**只给 eyeSmile 降级**——眉毛动不了就是动不了，拿嘴巴凑更怪 |
| D6 能力评分 | `FishModel.exprSlots()` 返回 `{score, direct, degraded, missing, rows[]}`。用户的模型能演多少，一眼看到 |

### 实测兼容性

| 模型形态 | 直连 | 降级 | 缺 | 评分 |
|---|---|---|---|---|
| 大肥鱼（规范名） | 23 | 0 | 0 | **100%** |
| 标准 Cubism（只有 Angle/EyeBall/EyeOpen/Mouth） | 9 | 1 | 13 | **60%** |
| 老模型改名（AngleX/EyeOpenL/MouthPucker 等） | 待重跑 | — | — | 目标 ≥85% |
| 只有头眼嘴 | 待测 | — | — | — |

### 待做

| 步骤 | 内容 |
|---|---|
| D7 适配器界面 | 模型适配器加一页「表情能力」：26 行槽位表，每行显示「已绑定 → 实际参数名」，带一个「试演」按钮（点一下演 2 秒该表情） |
| D8 体检集成 | `doctor.js` 的报告里加「表情能力 xx%」，缺的槽位列出来并给建议（「你的模型没有眉毛参数，眉毛相关表情会降级」） |
| D9 手动绑定持久化 | `PACK.params[slotId] = "ParamXxx"` 的用户手动映射要存进模型包，换机器不丢 |
| D10 模型包导出 | 适配器完成后，把 26 个槽位的绑定关系写进模型包 manifest，随包分发 |

## 7. 第 ③ 步「死参数剔除 + key 贴片」详解

这是这轮勘察里最有价值的发现，单独说。

**实测**：大肥鱼模型有 **509 个参数**，但用 A/B 对照探针测下来，真正驱动画面的只有约 **27 个**：

```
能动：ParamAngleX/Y/Z、ParamEyeLOpen/ROpen、ParamEyeBallX/Y、ParamMouthForm、
      ParamMouthOpenY、ParamBrowLY/RY、ParamBrowLAngle/RAngle、EyeSmile(弱)、
      JawOpen、MouthSmile_L(弱)、LCry/RCry、key1~key13、Movement1/2/3
不动：EyeSmile(强值无效)、ParamBrowRY(强值无效)、Mouthpucker、CheeckPuff、
      ShockL/R、Angry、ParamI、TongueOut、Emotion、IDLE、key4、SweatBurst1
```

**根因**：美术做了参数，但没把参数接到 ArtMesh 上（147 个部件不透明度恒为 1，key 参数写了不生效）。作者当年就踩过这个坑，注释写着「这条路是死的，别再试第二次」。

**所以第 ③ 步的含义**：

| 子项 | 做法 |
|---|---|
| ③-1 模型侧标注 | 在 `packs` 里给每个模型加一份「死参数黑名单」，`resolveExprSlot` 命中黑名单时自动降级，不再浪费时间写一个无效值 |
| ③-2 key 贴片 | `key1~key13` 是**开关型**（黑脸/落泪/圈圈眼/爱心眼/脸红/大牙/眼镜…），这些是美术唯一认真接过的表情。把它们当作「表情叠加贴片」：演「生气」时同时拉 `key1`（黑脸），演「爱心眼」时拉 `key4` |
| ③-3 自动探测 | 把探针（A/B 对照 + 顶点位移 + 不透明度差分）做成适配器里的「一键测活性」，跑完自动生成黑名单 |

**收益**：大肥鱼的表情观感立刻上一个台阶——现在「鼓脸闹别扭」演出来只有斜眼+嘴平（脸颊根本没鼓），贴上 `key1` 就是真的在闹脾气。

## 8. 尚未解决的硬限制（诚实清单）

| 限制 | 影响 | 出路 |
|---|---|---|
| 模型美术没接参数 | 一半表情参数是死的，97 段曲线只能演 60–70% 的语义 | 第 ③ 步 key 贴片 + 换模型 |
| 曲线库里没有「眨眼」 | 眨眼靠项目自己的眨眼逻辑（ACT_MERGE 的 min 已保证不被压掉） | 不用管，已正确 |
| 曲线库里没有「说话口型」 | 说话嘴型靠 TTS 的 `FishVoice.mouth()`（ACT_MERGE 的 max 已保证优先） | 不用管，已正确 |
| 头部角度会甩头 | 已用 `mix: 0.55` 缩到 55% | 可调，改 `mixedParams` 即可 |
| 无 onnx 语义 | 复杂/反讽/隐喻的文本认不准 | 方案 A 的 mood 先验 + 关键词表扩充 |
| 同标签段随机 | 同一情绪两次演出可能不一样 | 方案 C4（按 subcategory 挑） |
